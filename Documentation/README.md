# РТК CRM · кратко для жюри

Откройте [рабочую CRM](https://crm.futura.team/) или [публичную форму обращения](https://crm.futura.team/request/). Внутренние роли доступны по учётным данным, выданным команде отдельно. Для демонстрационной формы используйте только вымышленные сведения.

## Маршрут просмотра

1. В CRM откройте очередь КАМ и карточку активности. Посмотрите ответственного, текущую стадию, ближайшее действие и срок, историю и связанные сведения. В разделе «Как работать» есть короткий онбординг из пяти шагов; его можно открыть повторно из верхней панели. В меню «Обучение» собраны справочник этапов и каталог продуктов.
2. Перейдите к «Показателям команды» под руководителем. Здесь показаны открытые активности, просроченные действия, ожидание ответа, записи без следующего шага, разбиение по процессам и состояние ближайших задач. В разделе «Команда» можно открыть сотрудника и отфильтровать ленту его обновлений.
3. Откройте «Отчёты»: задайте фильтры, сформируйте срез и при необходимости файл. Готовые выгрузки доступны в очереди файлов. Роль КАМ видит только разрешённую ей область; системный администратор без бизнес-роли не получает отчётный доступ.
4. Под администратором откройте «Состояние системы» и изучите очереди CMS/LMS mock. Действия на этой странице работают с тестовыми сервисами стенда, а не с системами Ростелекома.

Публичная форма создаёт отдельное обращение для одного из трёх процессов. Для проверки его карточки и маршрута потребуется вход в CRM; отправка формы не открывает внутренние данные.

## Три процесса

| Процесс | Путь в CRM | Что учитывается отдельно |
| --- | --- | --- |
| Партнёрство с вузом | Первичный контакт → встреча и потребность → документы и согласование → внедрение → завершение | Пункты U01–U13 и сквозной обзор U14; возврат документов сохраняет предыдущее подтверждение и историю. |
| Индивидуальное обучение | Новая заявка → консультация → условия → передача в LMS → исключения и результат сопровождения | Контакт может быть без организации; запрос LMS, зачисление, начало и завершение обучения — отдельные факты. Старые записи сохраняют прежнюю версию маршрута. |
| Корпоративное обучение | Потребность компании → бриф и оценка → согласование программы → подготовка запуска → завершение | Плановая программа различает готовый курс, адаптацию и новую разработку. Заявленные места не становятся списком слушателей или зачислениями. |

Сервер проверяет допустимые переходы. Успешное закрытие корпоративной активности требует записанного согласованного объёма, дат, критериев приёмки и подтверждения с источником. Для текущего маршрута физлица нужен факт завершения из LMS. Отказ или отмена фиксируются отдельным итогом с причиной; принятие запроса LMS не означает обучение.

## Роли и повседневные функции

- **КАМ** работает со своей очередью, карточками, задачами, контактами и историей; получает внутреннее уведомление о назначенной заявке и пользуется разделом «Обучение».
- **Руководитель** смотрит командный портфель и отчёты в разрешённой области, открывает сотрудников и ленту обновлений в разделе «Команда», отслеживает задачи, импортирует данные после проверки и переназначает активность с предварительным просмотром последствий.
- **Администратор** управляет техническим доступом, общей схемой вузовского процесса, инструкциями и тестовыми обменами; для импорта ему доступна сводка без исходных строк. Совмещённая бизнес-роль предоставляет соответствующие бизнес-экраны.

Уведомления остаются внутри CRM: подписчики получают сведения об обновлении или завершении задачи. Чат, push и внешняя рассылка не входят в стенд. Интерфейс имеет светлую и тёмную темы и адаптируется к мобильной ширине; на узком экране доступны нижняя навигация, очередь и карточка.

## Аналитика, файлы и обмены

Руководителю доступны командный обзор и отчёты «Портфель CRM» и «Спрос и факты обучения». В срезах различаются активности CRM, заявленные места корпоративного плана и события LMS. Экспорт отчётов поддерживает XLS, XLSX, CSV UTF-8, PDF, JSON и PNG; набор колонок можно выбрать перед созданием файла.

Импорт проходит через загрузку, сопоставление полей, предпросмотр, валидацию и явное подтверждение. Поддерживаются XLS/XLSX/CSV для контактов и поставщиков, JSON/CSV для индивидуальных заявок. Совпадения и ошибки показываются для разбора; импорт не создаёт зачислений и учебных фактов.

Тестовый контур демонстрирует четыре направления: CMS → CRM (входящее обращение), CRM → CMS (подтверждение получения), CRM → LMS (запрос подготовки доступа), LMS → CRM (подтверждённое событие). Повторы защищены внешними ключами и ключами идемпотентности; учебная проекция CRM доступна только для чтения. Внешние CMS/LMS Ростелекома не подключены, а полнота данных этих систем неизвестна.
