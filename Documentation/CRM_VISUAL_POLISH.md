Работа выполнена в `codex/rtk-crm-visual`, отдельном worktree `rtk-crm-visual/LCT`, от `f6f3b74`. Основа решения — уже подготовленные `.agent/B2B_CRM_UX_SHORTLIST.html` и `.agent/CRM_VISUAL_OPTIONS_2026-09-29.md` из основного checkout. Повторный ресерч не проводился.

## Четыре изменения

1. **Дневной фокус КАМ.** Вместо четырёх одинаковых KPI — главный блок приоритетного сигнала с явным действием, спокойные вторичные сигналы и общая очередь в нижней строке. Приоритет: просрочки → отсутствие следующего шага → ожидание ответа. Если все три счётчика равны нулю — положительное состояние и переход ко всей очереди. Типографика Manrope, оранжевый акцент и семантические цвета остаются токенами Atomaro.
2. **Сравнение исключений.** Две горизонтальные полосы отвечают на вопрос: «Сколько открытых активностей затронуто каждым из остальных исключений?» Один главный сигнал показан слева, остальные два из трёх (просрочки, отсутствие шага, ожидание ответа) — полосами справа. Числитель — `total` соответствующей подборки `/api/activities`, знаменатель — `total` открытой очереди `collection=all` в той же области доступа. Значения подписаны `N / total`, нулевая выборка обрабатывается без деления на ноль. Подборки могут пересекаться, поэтому полосы не сложены в одну диаграмму и проценты не суммируются. Нажатие ведёт к точному фильтру. Кнопка обновления также обновляет нижний портфель.
3. **Ближайшее действие на виду.** Компактная строка над длинной карточкой показывает сохранённую ближайшую открытую задачу и её срок, остаётся видимой на большом экране и ведёт к задаче или раскрытой форме результата. На телефоне до 420 px и при низкой высоте окна закрепление отключено, чтобы не закрывать содержимое. Прокрутка учитывает высоту панели; фокус переносится в форму. Запись результата и изменение стадии остаются отдельными действиями.
4. **Контекстная хронология.** События сгруппированы по датам МСК, тип отделён от описания, время — от автора; задача, завершение, контакт, переход и документ имеют разные обозначения. Заметки выделены тихим фоном; ранние события раскрываются нативным `details`, в том числе с клавиатуры. Анимация появления 160 мс, hover и focus предусмотрены; `prefers-reduced-motion` отключает эффекты.

Дополнительно исправлена существовавшая в базовом commit ошибка TypeScript: таблица цветов сегментов не содержит `all` и теперь имеет корректный частичный тип. Поведение показателей руководителя не менялось.

## Использовано и отложено

Использованы «первый экран по роли и исключениям», «хронология + явный следующий шаг» и «живые детали без декора». Существующий pipeline сохранён.

Отложены боковой preview (его уже меняют в основном checkout), канбан физлиц и drag-and-drop, карта застоя с новой серверной агрегацией, расширение pipeline. Они потребовали бы пересечения с текущей работой других агентов или дополнительной проверки бизнес-маршрутов. Не изменялись Figma, импорт, страница «Команда», публичная форма, код API и рабочие базы данных. Светлая/тёмная тема повторно не проверялась. Нет деплоя и push.

## Проверка

- Frontend TypeScript: `tsc -p tsconfig.json`.
- API TypeScript и production Vite build выполнены теми же шагами, что в `npm run build`, с выводом в `/tmp/rtk-crm-visual/`: стандартная папка вывода worktree ограничена sandbox.
- Предупреждение Vite о JS chunk > 500 kB уже было в исходной сборке; новые зависимости не добавлены.
- Скриншоты исходной сборки и сборки после изменений сняты отдельным браузерным контекстом на одной теме. Браузер получает собранные файлы worktree и входит через локальный Keycloak. Исходные API на 3001/3003 возвращали HTTP 500: в рабочих базах отсутствует `public_demo_intakes`. Поэтому проверка проведена через API worktree на отдельной одноразовой копии существующей demo-базы; только к копии применён уже закоммиченный DDL 0032. QA-подключения принудительно read-only; адаптер читает те же права пользователя без записи last_seen_at и не запускает обслуживание обменов. Рабочие сервисы, данные и миграции не менялись. Для скриншотов данные не создавались и не менялись; метрики вычисляются из сохранённых записей стенда, а не из констант.

- Пройдены: переход главного сигнала в точную очередь, sticky следующего действия, раскрытие формы результата и перенос фокуса, раскрытие истории клавишей Enter на вузовской карточке, отсутствие горизонтального переполнения на 390/320 px, reduced motion. В итоговом запуске нет ошибок приложения или ответов API с ошибками.
- Перед OAuth callback тестовый браузер временно получает HTML уже запущенного dev-сервера; его служебные запросы 404 исчезают после загрузки изолированной production-сборки и не относятся к результату QA приложения.
- Фактические значения на снимках: 7 доступных открытых активностей, 0 просрочек, 0 ожидаемых ответов, 2 без следующего шага. Числа одинаковы до и после. Данные demo-среды являются сохранёнными синтетическими кейсами, не производственной статистикой. Новые показатели или события для иллюстраций не создавались.
- Одноразовая QA-база удалена после проверки. Стандартная папка `dist` и рабочие базы не использовались как место исправления внешней ошибки стенда.
