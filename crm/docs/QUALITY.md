# Проверки и открытые критерии CRM

Это реестр текущего локального стенда, а не акт приёмки заказчиком. Исходные критерии A01–A34 приведены в [RTK_CRM_GOAL.md](../../RTK_CRM_GOAL.md); карта макетов и узлов Figma — в [Gate B coverage](../../design/gate-b/coverage.md). `Код/тест` ниже означает только указанную автоматическую проверку. Реальное отображение в браузере и поведение клавиатуры требуют отдельного прохода.

**Последний проверенный срез (28.09.2026, A127).** `npm run build` и 77 обычных проверок прошли; отдельный PostgreSQL-набор — 22/22. Миграция 0031 вернула RT.Warehouse в каталог: эта позиция прямо названа в присланном описании файла поставщиков, и общий запрет на новые связи со скрытыми продуктами иначе мешал бы её импорту. В интерфейсе назначение Warehouse не выдумано. Самого исходного XLSX в этом checkout нет, поэтому импорт именно его содержимого не проверен. Отдельный архив исходников содержит только разрешённые пути `crm/`, без `.env.local`, `node_modules`, `.agent`, приватного хранилища и материалов delivery; распакованная копия установила зависимости и собралась. Первая офлайн-установка без наполненного npm-кэша невозможна; после обычного `npm ci` установка из кэша прошла без сети. PDF на 65 синтетических строках содержит все 65 записей и 12/12 номеров страниц; полнота и читаемость проверены извлечением текста и растровым просмотром. Отдельный генератор HTTPS-only realm прошёл положительный и три отрицательных случая. `build:public` с тремя примерными HTTPS-origin собрал JS с двумя нужными адресами и без localhost API/Keycloak; HTTP API в отрицательном случае отвергнут. Это проверка конфигурации и сборки, не production-запуска. Браузерные клики, мобильная компоновка, публичный TLS-хост и production-настройки Keycloak остаются неподтверждёнными. Судейский ZIP пока показывает компактный макет.

Владелец ответил «Ок» на прямой вопрос об утверждении предъявленного компактного Gate B (12 маршрутов, 15 основных и 6 вспомогательных кадров). Это согласование текущего макета, а не утверждение всех критериев A01–A34 или доказательство живого playback.

A101 · проверка JWT после замечания ревью: сервер теперь требует не только подписанный токен нужного issuer и `azp=lct-web`, но и `aud`, содержащий `lct-web`. Изолированный криптографический тест принимает корректный токен и отклоняет отсутствующую/чужую аудиторию, чужие `azp` и issuer. В действующем локальном Keycloak проверено только наличие claims (`aud=[lct-web,account]`, `azp=lct-web`, ожидаемый issuer) без вывода токена; тестовый вход в защищённый `/api/workflow` вернул HTTP 200. `npm test`: 73 pass, 18 штатных DB skip, 0 fail; `npm run build`: успешно. Новые DB-тесты не запускались, потому что менялась только верификация токена. Это не аудит публичного deployment или полная проверка OIDC-конфигурации иных контуров.

A102 · JSON-связи из Q&A: новые `report_snapshot_rows` в той же REPEATABLE READ транзакции сохраняют ID организации, контакта и плательщика, вариант корпоративной программы, ID/имена документов и ID договорно-лицензионных записей с documentId. Default JSON полного сохранённого среза выдаёт эти связи; внутренний `object_key` не выдаётся, выдача документа по ID остаётся отдельной scoped операцией. Старые срезы получают безопасные null/пустые массивы и не обогащаются после факта. Выбор колонок намеренно сокращает JSON-строки. На этапе A102 сущности учебной программы не было; A105 добавил её в каталог и карточку, A106 — в снимок и JSON-выгрузку. Проверки A102: `npm run build`, `npm test` (73 pass/18 skip), `npm run test:db` (18/18 pass).

A105 · отдельный каталог учебных программ: `learning_programs` хранит ручной приоритет 1–5 независимо от приоритета активности и продуктов; `activity_programs` связывает одну программу с несколькими активностями и наоборот. КАМ видит число только своих связанных активностей, руководитель — доступной команды, технический администратор — ноль без бизнес-роли. Изменение приоритета проверяет ревизию; связь редактируется в карточке с общей ревизией основных сведений и записью в историю. UI использует компактную секцию в существующем справочнике и выбор в карточке, без нового раздела навигации. Root: `npm run build` — успешно; `npm test` — 74 pass, 19 штатных DB skip; `npm run test:db` — 19/19 pass; существующий локальный API после миграции вернул `GET /api/programs` HTTP 200 с пустым каталогом. DB-набор проверяет дубликат названия без учёта регистра, привязки, область КАМ/руководителя/администратора и конфликт ревизии. Реальное отображение и клавиатура по-прежнему не проверены браузером.

Q&A допускает КАМ **или** администратора для ручного ранжирования; выбран административный вариант с дополнительным правом руководителя. 1. На разрешённом UI-канале пройти три процесса и три роли на широком и узком экране, клавиатуру, сохранение/конфликт/отказ, сверить Atomaro и Figma. Согласование владельцем текущего Gate B не подменяет эту техническую проверку.
