# КАМ: положение процесса и следующий рубеж

## Решение

В рабочем дашборде КАМ после четырёх верхних показателей показываем компактный обзор активных взаимодействий. Карточка каждой записи явно разделяет сохранённую текущую стадию (`stageLabel`) и следующий переход, возвращённый сервером (`allowedNextLabels`). Это операционная карта «где сейчас → куда можно перейти», а не процент выполнения, прогноз конверсии или линейный канбан.

Показываем три типа взаимодействий: партнёрства с вузами, корпоративное обучение и индивидуальное обучение. Для индивидуального обучения сохраняем отдельные маршруты legacy и v2. Внутри каждого маршрута показываем до четырёх первых записей списка API и точное общее число; выдача API уже приоритизирует записи по приоритету, сроку следующей задачи и свежести. В карточке дополнительно показываем ожидаемый ответ и ближайшую открытую задачу, когда они есть.

Если сервер вернул несколько следующих стадий, подпись — «Доступные переходы» с их названиями. Пустой список обозначается «Нет следующего перехода в схеме»; компонент не трактует его как завершение процесса. Закрытые записи не попадают в выборку, так как очередь API возвращает только открытые активности.

## Контракт и интеграция

- Компонент: `web/src/KamPipeline.tsx`; стили изолированы в `web/src/KamPipeline.css`.
- API: `GET /api/activities?segment=…&collection=all&offset=0&limit=4`; у индивидуальных маршрутов добавляется `routeVersion=legacy|v2`. Авторизация и фильтрация области КАМ остаются серверными.
- Props: `api` — существующий типизированный API-вызов; `onOpenQueue(segment, routeVersion?)` — переход в очередь. Родитель пробрасывает `routeVersion` в фильтр очереди, поэтому кнопка физлиц открывает только выбранный маршрут.
- Точка размещения: после верхних KPI в `KamDashboard`; текущую декоративную процентную полосу «структура портфеля» удалить. Сам блок не меняет маршрут активности и не предлагает переход стадии.
- Источник UI-токенов: локальные `--crm-*`, связанные с сохранёнными Atomaro-derived токенами. Это локальная CRM-композиция, не заявленная official Atomaro component.

Графика построена на счётчиках и фактических переходах. Отношение «заполненности» к выдуманной цели не показывается; четыре запроса остаются независимыми срезами, поэтому компонент не строит составную диаграмму, которая могла бы подразумевать единый атомарный snapshot.
